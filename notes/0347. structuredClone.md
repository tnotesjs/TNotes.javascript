## 1. 导读

`structuredClone` 是平台提供的深拷贝 API（挂在 `Window` / Worker 全局上；Node 17+ 也有同名全局）。

它走的是 **结构化克隆算法**（和 `postMessage`、IndexedDB 存对象用的是同一套思路）。

比 `JSON.parse(JSON.stringify(x))` 更强：支持 `Map` / `Set` / `Date` / `ArrayBuffer`、循环引用等；比手写递归拷贝更省心。

## 2. `structuredClone` 简介

`structuredClone` 作用：用结构化克隆算法，对给定值做 **深拷贝**。

通过 `options.transfer`，把部分 **可转移对象** 从原值 **挪** 到克隆结果上（不是拷贝一份，原值里对应部分会失效）。

### 2.1. 语法

```js
structuredClone(value)
structuredClone(value, options)
```

- `value`：要克隆的值（须是结构化克隆支持的类型）。
- `options.transfer`（可选）：可转移对象数组；这些对象会被 **转移** 到返回值，而不是再拷一份。
- 返回值：`value` 的深拷贝。
- 异常：若任一部分不可序列化，抛出 `DataCloneError`（`DOMException`）。

### 2.2. 基本用法

```js
const original = { name: 'MDN' }
original.itself = original // 循环引用

const clone = structuredClone(original)

console.assert(clone !== original)
console.assert(clone.name === 'MDN')
console.assert(clone.itself === clone) // 循环引用被保留
```

- 克隆后是 **另一个对象**（`!==`），值相同，循环引用仍指向克隆自己。

## 3. 能克隆什么、不能克隆什么

能克隆（常见）：

- 除 `symbol` 外的基本类型
- 普通对象、`Array`
- `Map` / `Set`
- `Date`、`RegExp`（`lastIndex` 不会保留）
- `ArrayBuffer`、`TypedArray`、`DataView`
- 部分 `Error` 类型（`name` / `message` 会序列化；其它字段看实现）

不能克隆（会抛 `DataCloneError`）：

- `Function`
- DOM 节点
- `Symbol`（作为值）
- 多数带内部槽、无法结构化序列化的平台对象

不会保留的元数据：

- 属性描述符、getter / setter
- 原型链上的属性（只克隆「自有、可枚举」那一套结构化视图，类实例会变成普通对象形态）

## 4. `transfer`：转移所有权

可转移对象（如 `ArrayBuffer`）可以放进 `transfer`：所有权挪到克隆侧，原侧对应 buffer **不可再用**（常见表现是 `byteLength === 0`）。

适合大块二进制：避免再拷一份内存，也避免两边同时改同一块 buffer。

```js
const uInt8Array = Uint8Array.from({ length: 1024 * 1024 }, (_, i) => i)

const transferred = structuredClone(uInt8Array, {
  transfer: [uInt8Array.buffer],
})

console.log(uInt8Array.byteLength) // 0 —— 已转移走
console.log(transferred.byteLength) // 仍然是原来的长度
```

## 5. 与 `JSON` 深拷贝、浅拷贝的对比

| 方式 | 深拷贝？ | 循环引用 | `Map`/`Set`/`Date` | `undefined` / 函数 | 典型代价 |
| --- | --- | --- | --- | --- | --- |
| 赋值 / 展开一层 | 否（浅） | — | 引用共享 | 保留引用 | 最快，易踩共享引用 |
| `JSON.parse(JSON.stringify(x))` | 近似深 | ❌ | `Date`→字符串；`Map`/`Set` 丢 | 函数、`undefined` 常丢 | 只适合「纯 JSON 数据」 |
| `structuredClone(x)` | 是 | ✅ | ✅ | 函数等不可克隆会抛错 | 通用深拷贝首选 |

需要「和 `postMessage` 能传的那套数据」一致时，优先 `structuredClone`。

只要纯 JSON、且已接受 `JSON` 的丢弃规则时，`JSON` 往返仍可用。

## 6. 示例 1：基本深拷贝

```js
const mushrooms1 = {
  amanita: ['muscaria', 'virosa'],
}

const mushrooms2 = structuredClone(mushrooms1)

mushrooms2.amanita.push('pantherina')
mushrooms1.amanita.pop()

console.log(mushrooms2.amanita) // ['muscaria', 'virosa', 'pantherina']
console.log(mushrooms1.amanita) // ['muscaria']
```

两边数组互不影响 → 确实是深拷贝。

## 7. 示例 2：不可克隆值与 `DataCloneError`

```js
try {
  structuredClone({ fn: () => {} })
} catch (e) {
  console.log(e.name) // DataCloneError
}

try {
  structuredClone(document.body)
} catch (e) {
  console.log(e.name) // DataCloneError
}
```

函数、DOM 节点都不能过结构化克隆；需要这些时，换方案（只传可克隆数据、或自己挑字段）。

## 8. 示例 3：`transfer` 转移 `ArrayBuffer`

```js
const buffer1 = new ArrayBuffer(16)
const object1 = { buffer: buffer1 }

const object2 = structuredClone(object1, { transfer: [buffer1] })

const view2 = new Int32Array(object2.buffer)
view2[0] = 42
console.log(view2[0]) // 42

// 原 buffer 已转移，再包一层 TypedArray 会出问题
try {
  new Int32Array(object1.buffer)
} catch (e) {
  console.log(e.name) // TypeError（实现上常见）
}
```
